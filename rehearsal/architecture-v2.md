# Architecture v2 — FICTIONAL OFFLINE REHEARSAL

Supersedes v1 for brief-v2's session revision, retaining all other design choices. Live status awaiting-owner. Lesson `server-owned-prices` v1 remains cited and enforced; forged totals are still ignored in favor of integer-paise catalog prices.

`policy.ts` enables exactly morning 24 and evening 16. Add non-null session to existing rows with default morning in an immediate transaction after verifying all existing daily allocations are at most 24. Abort before ALTER/UPDATE on over-capacity legacy data. New POSTs must specify a valid session; validate against own policy properties. Capacity queries include date and session. Existing record fingerprint already included the implicit morning value, preserving duplicate protection after migration. Owner list sorts date/session, and customer confirmation shows that exact session/window.

The rehearsal wrapper stops the previous container, takes a SQLite backup and preflights legacy capacity before replacing it. On preflight failure it restarts the old instance and reports an owner-decision blocker. Persistent bind mount is retained across deployments. The new app migrates only while the old writer is stopped. The shared deployer initially starts a health-only bootstrap because it cannot inject required mounts; the wrapper then attaches the storage/credential mounts, pins the allocated host port across recreation and checks version 2 before any HTTP flow. This is an explicit kit workaround, not production-ready deployment atomicity. A failed final mount/migration can leave the application unavailable; manual rollback with the backup is outside this rehearsal.

Tests: migration preserves a known morning order, over-24 case leaves old schema/data unchanged, session validation, 23/+2/reject/+1, separate evening16, last-unit race, idempotency, restart, forged prices, exact cut-off and private access. Previous approvals are reopened; real live approvals remain absent.
