Must fix before real keys:

1. **Critical — agent-controlled Git configuration executes as studio.** [desk/src/real-loop.ts:287](/home/varun/hackathonprojects/backroom/desk/src/real-loop.ts:287), [deploy/nixos/dev.nix:78](/home/varun/hackathonprojects/backroom/deploy/nixos/dev.nix:78). An agent can edit a workspace’s `.git/config`, set `core.fsmonitor` to an attacker-written executable, then trigger the checkpoint check at `real-loop.ts:315`. `git status` executes that program as `studio`. Disabling hooks does not disable filesystem monitors. **Impact:** access to studio’s GitHub login, signing key and `.secrets`, followed by root access through finding 3; approvals become bypassable. **Smallest fix:** immediately force `core.fsmonitor=false` on every privileged Git invocation. Close the broader configuration boundary by running workspace Git as `agent` and using a separate studio-owned repository for authenticated operations.

2. **High — replacement refs defeat exact-commit binding.** [deploy/nix-deployer.ts:130](/home/varun/hackathonprojects/backroom/deploy/nix-deployer.ts:130), [deploy/nix-deployer.ts:196](/home/varun/hackathonprojects/backroom/deploy/nix-deployer.ts:196). After review, an agent can add `.git/refs/replace/<approved-SHA>` pointing to a malicious commit. `rev-parse` still identifies the approved SHA, while `show`, tree reads and archive generation can use its replacement. On a first deployment, malicious source can therefore be imported under the approved SHA; the required-key declaration can also be substituted. **Impact:** deployment of unreviewed code that receives real runtime keys. **Smallest fix:** set `GIT_NO_REPLACE_OBJECTS=1` consistently across review, declaration, diff and archive commands; perform release reads from protected Git metadata.

3. **High — studio has unrestricted root authority through multiple paths.** [scripts/studio-install-tools.sh:28](/home/varun/hackathonprojects/backroom/scripts/studio-install-tools.sh:28), [deploy/nixos/dev.nix:103](/home/varun/hackathonprojects/backroom/deploy/nixos/dev.nix:103). The installed SSH key restricts source address and forwarding but has no forced command: compromised studio can request any root command over localhost. Independently, the root Switch service executes a studio-owned script and consumes studio-owned Compose configuration. **Attack:** obtain studio execution through finding 1, then use localhost SSH immediately—or modify root-consumed artifacts for the next service start. **Impact:** root deploy key, Switch database, metadata credentials and deployment control. **Smallest fix:** replace shell SSH access with a root-owned, strictly allowlisted deployment broker; make every root-executed script and Compose file root-owned and unwritable by studio.
